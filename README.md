# Hackathon Go1, заочный этап: T2 Safety Block

ROS 2 Humble узел, который проверяет команды из `/lowcmd_bare` и публикует безопасные команды в `/lowcmd`
(Unitree Go1, MuJoCo Lowlevel). Реализовано задание T2. Режим `ping` отвечает по протоколу 1.0 из задания T1.
Задания T3, T4 и T5 в этом образе не реализованы.

## 2. Интерфейсы ROS 2

| Топик | Тип | Направление | QoS узла |
|---|---|---|---|
| `/lowcmd_bare` | `unitree_go/msg/LowCmd` | вход, команды для проверки | подписка BEST_EFFORT, глубина 10 |
| `/lowstate` | `unitree_go/msg/LowState` | вход, телеметрия | подписка BEST_EFFORT, глубина 10 |
| `/lowcmd` | `unitree_go/msg/LowCmd` | выход, безопасные команды | публикация RELIABLE (по умолчанию), глубина 10 |
| `/clock` | `rosgraph_msgs/msg/Clock` | вход, симуляционное время | через `use_sim_time = true` |

Порядок суставов во всех сообщениях: FR, FL, RR, RL, внутри каждой ноги hip, thigh, calf (индексы `motor_cmd` 0–11).
Элементы 12–19 массива `motor_cmd` не используются и остаются нулевыми. Переменные `ROS_DOMAIN_ID`,
`RMW_IMPLEMENTATION` и `CYCLONEDDS_URI`, переданные запускателем, узел не меняет.

## 3. Как работает блок безопасности

Блок хранит три величины: текущую выходную уставку `q_cur`, последнюю принятую безопасную цель `q_tgt` и текущие `kp`, `kd`.

**Инициализация.** Первая выходная уставка берётся из первого `/lowstate` (измеренные положения, обрезанные по пределам).
Если `/lowstate` не пришёл за 1 секунду симуляционного времени после появления `/clock`, берётся запасная стойка
`[0, 0.9, -1.8]` для каждой ноги. До появления `/clock` блок ничего не публикует.

**Проверка входной команды** (при каждом сообщении из `/lowcmd_bare`):

1. Если в любом из полей `q`, `dq`, `tau`, `kp`, `kd` любого из 20 элементов `motor_cmd` есть NaN, +Inf или −Inf,
   сообщение отклоняется целиком, цель и коэффициенты не меняются.
2. Целевые углы 12 суставов обрезаются по таблице п. 4.3 ТЗ (hip ±0,863; thigh от −0,686 до 4,501;
   calf от −2,818 до −0,888) с запасом 0,001 рад внутри диапазона.
3. `kp` ограничивается диапазоном 0–1000, `kd` диапазоном 0–100.
4. Для обрезанной цели считается глубина самоколлизии. Если она больше порога, команда отклоняется: блок продолжает
   идти к прежней цели и использует прежние `kp`, `kd`. Иначе цель принимается.

Входные `mode`, `dq` и `tau` не используются: на выходе всегда `mode = 0x0A`, `dq = 0`, `tau = 0`.

**Выход** (таймер 100 Гц по симуляционному времени):

1. Считается разница между принятой целью и текущей уставкой. Шаг ограничивается 3° (ТЗ допускает 5°) по самому
   большому из суставов, остальные суставы масштабируются пропорционально.
2. Шаг от `q_cur` к кандидату проверяется по прямой в пространстве суставов с дискретностью 0,1° (как у Judge).
   Если на пути есть запрещённое проникновение, шаг уменьшается вдвое, до пяти попыток. Если все попытки неудачны,
   уставка остаётся прежней и блок пробует снова на следующем тике.
3. Если стартовая поза уже содержит проникновение, блок не допускает его увеличения.
4. Публикуется `LowCmd`: для суставов 0–11 `mode = 0x0A`, `q = q_cur`, `dq = 0`, `tau = 0`, текущие `kp`, `kd`.

**Самоколлизия.** Используется модель `unitree_go1/scene.xml` (MuJoCo 3.3.7) и перечень `t2_collision_pairs.csv`.
Идентификаторы геометрий в CSV посчитаны по `scene.xml` (пол имеет id 0), поэтому модель грузится из сцены, а не из `go1.xml`.
Проверяемыми считаются 655 пар, у которых в столбце `diagnostic_policy` стоит значение `checked`
(остальные категории: `floor exclusion` 55, `same welded body` 102, `parent/adjacent filter` 246, `mask exclusion` 482).
Для конфигурации выставляются углы суставов, выполняется кинематика и поиск контактов, глубина берётся по контактам
из перечня. Порог 0,8 мм: меньше запрета ТЗ (строго более 1 мм) для запаса.

**Потеря входного потока.** Отдельного режима нет. Публикация идёт независимо от входа, поэтому при молчании
`/lowcmd_bare` выход продолжается, уставка сходится к последней принятой цели и остаётся на ней, `dq = 0`, `tau = 0`,
`kp` и `kd` последние допустимые. Это удержание принятой цели, а не измеренного положения.

**Журнал.** Раз в 5 секунд узел печатает `accepted=N rejected=M`, где `rejected` включает сообщения с NaN/Inf и цели
с самоколлизией. При старте печатаются разбивка `diagnostic_policy` и число проверяемых пар (ожидается 655).

## 4. Параметры узла

Параметры задаются при запуске узла (по умолчанию в образе не меняются).

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `model_path` | `<каталог скрипта>/unitree_go1/scene.xml` | Модель MuJoCo |
| `pairs_path` | `<каталог скрипта>/unitree_go1/t2_collision_pairs.csv` | Перечень пар |
| `rate_hz` | 100.0 | Частота публикации `/lowcmd` |
| `max_step_deg` | 3.0 | Максимальный шаг сустава между выходными сообщениями (лимит ТЗ 5°) |
| `check_res_deg` | 0.1 | Дискретность проверки перехода |
| `pen_tol_m` | 0.0008 | Допустимое проникновение, м |
| `kp_default`, `kd_default` | 40.0, 1.0 | Коэффициенты до первой принятой команды |
| `kp_max`, `kd_max` | 1000.0, 100.0 | Верхние пределы по ТЗ |

Если MuJoCo или файл модели недоступны, узел продолжит работу без проверки самоколлизий и напишет об этом в лог.
Это аварийный режим, для сдачи он недопустим.

## 5. Режимы запуска образа (`/entrypoint.sh`)

Образ запускается как `/entrypoint.sh <режим>`. По умолчанию (`CMD`) режим `T2`.

| Режим | Что делает | Выход |
|---|---|---|
| `ping` | Печатает в stdout ровно один JSON и завершается с кодом 0 за доли секунды, ROS не запускается | `{"protocol_version":"1.0","supported_tasks":["T2"],"self_trained_rl":false,"preferred_speed_mps":null}` |
| `T2` | Подключает ROS 2 Humble и рабочее пространство `go1_ws`, запускает `/opt/t2/safety_block.py` и работает до остановки контейнера | Узел `safety_block`, логи в stderr |
| `T3`, `T4`, `T5`, любое другое | Не реализовано: сообщение в stderr, код возврата 2 | пустой stdout |

В режиме `ping` диагностика не пишется в stdout. Значения полей: `self_trained_rl = false` (RL не использовался),
`preferred_speed_mps = null` (T3 не реализовано). Если в будущем появится T3, список `supported_tasks` и эти поля
нужно обновить.

## 6. Сборка образа

Нужна папка `unitree_go1` из репозитория публичного симулятора (`models/mujoco/unitree_go1`).
SHA-256 эталонного `go1.xml` по ТЗ: `d5a7466784c8e72fd174cc7fa5a92754a1a0a6d458a1dec79e7ca0abc9525c4a`.

Автоматически:

    SIM_REPO=~/go1-simulator-public bash build.sh

Переменные `build.sh`: `SIM_REPO` (путь к клону симулятора, по умолчанию `~/go1-simulator-public`), `SIM_IMAGE`
(базовый образ симулятора), `IMAGE_TAG` (тег результата, по умолчанию `t2-safety`). Скрипт останавливается, если
хеш `go1.xml` не совпал.

Вручную:

    cp -r ~/go1-simulator-public/models/mujoco/unitree_go1 .
    sha256sum unitree_go1/go1.xml
    docker build -t t2-safety .
    # с явным базовым образом:
    docker build --build-arg SIM_IMAGE="$SIM_IMAGE" -t t2-safety .

Базовый образ по умолчанию: `registry.cookcloud.ru/go1-hackathon-remote-stage/go1-sim:v1.0`. В нём есть ROS 2 Humble,
сообщения `unitree_go` и пользователь `ros`. В образ при необходимости доустанавливаются `mujoco` и `numpy`
(в проверенной сборке версия MuJoCo 3.3.7, что совпадает с ТЗ). Проверка версии:

    docker run --rm --entrypoint python3 t2-safety -c "import mujoco; print(mujoco.__version__)"

Интернет нужен только на этапе сборки. Образ запускается от пользователя `ros` без прав root.

## 7. Проверка допуска T1

    docker image inspect t2-safety --format '{{.Os}}/{{.Architecture}}'      # ожидается linux/amd64
    docker run --rm --entrypoint cat t2-safety /etc/os-release | head -2      # Ubuntu 22.04
    docker run --rm --entrypoint id t2-safety                                # uid не 0
    time docker run --rm --network none t2-safety ping; echo "код: $?"       # до 10 с, код 0
    docker run --rm --network none t2-safety ping 2>/dev/null | python3 -c 'import json,sys; print(json.load(sys.stdin))'

Требования ТЗ к образу: linux/amd64, Ubuntu 22.04, ROS 2 Humble, Cyclone DDS (`rmw_cyclonedds_cpp`), только CPU,
запуск без root, без интернета во время испытаний, исполняемый `/entrypoint.sh` в корне.
Организаторы проверяют образ по SHA-256 digest, формат и время `ping` и работу без сети.

## 8. Локальный запуск с симулятором

Из корня репозитория публичного симулятора (`~/go1-simulator-public`):

    export SIM_IMAGE=registry.cookcloud.ru/go1-hackathon-remote-stage/go1-sim:v1.0
    python3 run_local.py --task T2 --sim-image "$SIM_IMAGE" --participant-image t2-safety --gui --logs

Что должно появиться в логе: `Simulator ready`, `Pair started`, затем строки узла `safety_block`:
разбивка `diagnostic_policy` и `Пар для проверки: 655 (ожидается 655)`, далее `accepted/rejected` раз в 5 секунд.
Имя контейнера Participant печатается в строках `Simulator=...` и `Participant=...`; оно меняется при каждом запуске.
Остановка: Ctrl+C в терминале запускателя. Локальный запускатель не заменяет закрытый Judge.

Режим без окна: `--headless` вместо `--gui`. Команда для справки по аргументам: `python3 run_local.py --help`.

## 9. Проверочные скрипты и их режимы

Все скрипты запускаются внутри контейнера Participant при работающей паре. Общий шаблон:

    docker exec -it <имя_participant_контейнера> bash -c 'source /opt/ros/humble/setup.bash; source /home/ros/go1_ws/install/setup.bash; python3 <скрипт> <аргументы>'

Скрипты `judge_sim.py` и `probe.py` сначала копируются:

    docker cp judge_sim.py <имя_participant_контейнера>:/tmp/judge_sim.py
    docker cp probe.py <имя_participant_контейнера>:/tmp/probe.py

Копия действует только для этого контейнера: после перезапуска пары копировать нужно заново. Для чистой картинки в окне MuJoCo
перед проверкой лучше запускать свежую пару, потому что после тестов с экстремальными командами робот остаётся опрокинутым.

### 9.1. `selftest.py` (в образе: `/opt/t2/selftest.py`)

Около 14 секунд симуляционного времени: 0–6 с безопасное плавное движение, 6–8 с сообщения с NaN, 8–10 с углы вне
диапазона, 10–14 с входной поток молчит. В конце печатает одну строку: частота, максимальный интервал, максимальный
шаг, число значений вне пределов, число сообщений с NaN. Если с `/lowcmd` не пришло сообщений, пишет об этом.

### 9.2. `collision_test.py` (в образе: `/opt/t2/collision_test.py`)

Использует код проверки коллизий самого блока, поэтому проверяет согласованность, а не независимо.

- Часть A: 15 случайных конфигураций с проникновением больше 3 мм, выход проверяется с шагом 0,1°.
- Часть B: пары безопасных поз, прямой путь между которыми проходит через коллизию.
- Часть C: удержание последней принятой цели при молчании входа (отклонение выхода от цели после 0,5 с тишины).

### 9.3. `judge_sim.py` (копировать в контейнер)

Имитация Judge по п. 4.5 ТЗ. Коллизии считаются независимо от блока через `mj_geomDistance` по 655 парам.
Шесть сценариев по порядку: частота и интервал (окно 5 с), сходимость допустимых команд, NaN и Inf в разных полях
(включая неиспользуемый элемент 15), удержание при потере входа, пределы суставов, самоколлизии. В конце выставляет
оценку по таблице критериев (из 15). Это локальная оценка по тексту ТЗ, а не результат закрытого Judge.
Запуск занимает несколько минут.

### 9.4. `probe.py` (копировать в контейнер)

Ручная отправка команды в `/lowcmd_bare` с частотой 50 Гц и просмотр `/lowcmd` раз в 0,5 с sim-времени
(углы ноги FR, число сообщений в секунду, число нечисловых сообщений на выходе, отклонение выхода от цели).

| Команда | Что посылает | Что ожидается на выходе |
|---|---|---|
| `python3 /tmp/probe.py stand 3` | Стойка `[0, 0.9, -1.8]` на 3 с | Выход приходит в цель |
| `python3 /tmp/probe.py crouch 3` | Присядка `[0, 1.2, -2.4]` | Выход приходит в цель |
| `python3 /tmp/probe.py extreme 3` | Углы вне диапазона `[3, 9, 1]` | Выход упирается в границы таблицы (0,862; 4,5; −0,889) |
| `python3 /tmp/probe.py nan 2` | Сообщение с NaN в `q[3]` и корректными остальными | Выход не меняется, NaN на выходе 0 |
| `python3 /tmp/probe.py silence 3` | Ничего не шлёт | Поток продолжается, значения не меняются |
| `python3 /tmp/probe.py q "<12 чисел>" 3` | Свои углы в порядке FR, FL, RR, RL (hip, thigh, calf) | Зависит от цели |

Режимов, подбирающих конфигурации с коллизией, и вывода глубины проникновения в `probe.py` нет: коллизии
проверяют `collision_test.py` и `judge_sim.py`. Первый аргумент скрипта задаёт режим, последний длительность в секундах
симуляционного времени.

## 10. Результаты локальных проверок

| Проверка | Результат |
|---|---|
| Хеш `go1.xml` | Совпал с ТЗ |
| Число проверяемых пар | 655 из 1540 |
| `ping` | Один JSON, код 0 |
| `selftest.py` | 75,4 Гц, макс. интервал 50 мс, макс. шаг 3,00°, вне пределов 0, NaN 0 |
| `collision_test.py` | A: 708 сообщений, нарушений 0; B: 854 сообщения, нарушений 0, макс. 0,54 мм; C: отклонение 0,0000 рад |
| `probe.py` | `stand`, `crouch` приходят в цель; `extreme` упирается в границы; `nan` отклонён; `silence` удерживает цель |
| `judge_sim.py` | 92,0 Гц, макс. интервал 32 мс; допустимые команды отработаны; NaN 0 на выходе; удержание 0,0000 рад; вне пределов 0; коллизии: 1518 сообщений, нарушений 0, макс. 0,33 мм, макс. шаг 3,00°; локальная оценка 15 из 15 |

Требования ТЗ для сравнения: частота не ниже 50 Гц за 5 с sim-времени, максимальный интервал не более 100 мс,
изменение угла между сообщениями не более 5°, проникновение не более 1 мм, удержание цели через 0,5 с.
Запас по частоте зависит от нагрузки машины (в разных запусках 62–92 Гц), на сервере организаторов он может быть меньше.
